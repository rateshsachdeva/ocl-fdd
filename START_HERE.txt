OCL FDD - START HERE
====================

1. Put the raw client Excel files in:
       references/source/

2. Install Python dependencies:
       pip install -r requirements.txt

   Python 3.11 is recommended.

3. OPTIONAL - teach a difficult source one workbook at a time.

   For large or structurally difficult files, run for example:

       python run_all.py --learn-source Finance_Pack.xlsx
       python run_all.py --learn-source Balance_Sheet_Detail.xlsx

   This runs data preparation / AI understanding for only the selected source,
   promotes safe reusable knowledge, and stops before building the final OCL
   Excel/PPT. The original file is copied for learning and is not modified.

   Repeat for other difficult sources if useful. Then leave all relevant client
   files together in references/source/ for the final engagement run.

4. Choose one GitHub Copilot route for the final run.

   A) VS Code GitHub Copilot coding agent (recommended for a recipient with
      GitHub Copilot Enterprise):

      Ask the agent to run the skill end to end and follow AGENTS.md.
      The repository instructions use:

       python run_all.py --ai-host external

   B) Plain terminal / PowerShell:

       copilot --version
       copilot login --web-flow
       python run_all.py

      For this route, Copilot CLI must be installed, authenticated, and allowed
      by the recipient's organization/enterprise policy. A Copilot Enterprise
      seat alone does not override an organization policy that disables CLI.

5. The normal workflow is:
       raw Excel
         -> Python profiling / prepared evidence
         -> Python matches compact reusable knowledge to current profile
         -> AI: UNDERSTAND_AND_PLAN
         -> Python deterministic execution + completeness + lineage
         -> OCL reviewed judgments + hard controls
         -> Python databook + evidence-aware analysis
         -> AI: FDD-partner Deal Issues + Key Findings + Q&A
         -> Python styling + final QA + PPT
         -> versioned final publication

   Reusable knowledge is supporting evidence only. Current source evidence wins.
   Production AI must not use historical synthetic golden-truth/test-answer files
   as an answer key.

6. A HUMAN / REVIEW_OCL_JUDGMENTS checkpoint is intentional for a new source when
   scope, category/hierarchy, WC/debt-like or normal/one-off treatment has not
   been reviewed yet. Review the generated review artifacts and rerun. Do not
   force AI to mark an unsupported accounting/FDD judgment as reviewed.

7. Evidence-aware analysis:
       Analysis Coverage
       Seasonality / monthly volatility
       Year-end build / unwind
       Recurrence / persistence proxy
       Normalization reference (not an automatic adjustment)
       Stale-balance / new-balance / cliff diagnostics
       Debt-like / one-off / concentration
       Movement utilisation / release / reversal when movement data exists
       Accrual-to-expense only when explicit expense/P&L context exists

   Adequacy, missing-accrual completeness, double counting and true aging are
   NOT inferred from aggregate balance history. They remain unsupported/partial
   unless the required detailed evidence is actually supplied.

8. Final deliverables are versioned on every completed final run:
       output/OCL_Databook_v1.xlsx
       output/OCL_Report_v1.pptx

   The next completed run creates v2, then v3, and so on. Existing versioned
   deliverables are never overwritten.

AI CHECKPOINT SAFETY
--------------------
Python owns source values, calculations, reconciliations, controls and rendering.
AI writes only the contextual reasoning artifacts requested by workflow
coordination. Every required AI artifact must be newly created/updated before the
workflow can advance.

If an external agent is used for --learn-source, rerun the exact resume_command
printed by workflow coordination so the same learning source remains selected.

If the terminal route reports missing authentication, run:

       copilot login --web-flow

If the organization blocks Copilot CLI, use the VS Code coding-agent route.

See HANDOFF_TO_NEW_USER.md for the complete recipient checklist.

Do not commit client source files. references/source/ is intentionally ignored by Git.
Do not bypass failed controls or create balancing plugs.
